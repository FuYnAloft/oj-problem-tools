# description.md 规范

## Frontmatter

把 YAML frontmatter 放在文件第一行，并用 `---` 包围。虽然解析器兼容把它放在一级标题之后，但那会产生警告，不要使用兼容写法。只保留一块 frontmatter。

支持写入 OpenJudge 的字段：

- `timeLimit`：整题时间限制，单位 ms。按目标语言和最大数据选择，避免宽松到无法区分劣解。
- `caseTimeLimit`：单个测试点时间限制，单位 ms；不需要时省略。确保不与总时间限制矛盾。
- `memoryLimit`：内存限制，单位 kB。应覆盖标准解峰值并留合理余量。

题名不写在 frontmatter；它来自正文中唯一的一级标题。

可选的 `config` 只控制题面渲染：

```yaml
config:
  style: github-tweaked
  widening: 0
  singleLineBreak: true
  stripOjRemove: true
```

- `style`：`none`、`github`、`github-tweaked` 或 `github-tweaked-compact`；默认 `github-tweaked`。
- `widening`：题面区域增加的宽度，单位 px，必须是有限数字；默认 `0`。
- `singleLineBreak`：是否把普通单换行渲染为 `<br>`；默认 `true`。
- `stripOjRemove`：是否删除 `:::oj-remove` 块；默认 `true`。

通常只写三个限制字段，让 `config` 使用默认值。推荐骨架：

```markdown
---
timeLimit: 1000
caseTimeLimit: 100
memoryLimit: 65536
---

# 题目名称
```

## 正文结构

全文必须恰好有一个一级标题。二级章节按题目需要增删，通常包括：

1. `描述`：说明对象、目标和规则，定义术语。
2. `输入格式`：逐行说明字段、类型、数据范围、字符集、下标起点及是否有多组数据。
3. `输出格式`：逐行说明内容、顺序、空格、排序、并列、无解和精度规则。
4. `样例`：输入输出成对出现，代码块使用 `text`；多个样例使用连续编号。
5. `样例解释`：复杂题建议写，简单题可省略。
6. `数据范围与提示`：分档范围、算法提示或额外保证，可省略但不能隐藏正确性所需条件。
7. `来源`：可省略。

## 写作检查

- 给所有会影响答案的边界下定义：闭区间还是开区间、能否为空、元素能否重复、名称是否唯一。
- 明确并列选择和排序的全部关键字及升降序。
- 明确除法、舍入、取模、溢出和负数语义。若要求四舍五入，说明位数及舍入规则。
- 区分“保证输入合法”和“程序需要处理非法输入”。竞赛题通常只要求处理合法输入。
- 数据范围必须与生成器完全一致；不要生成题面没允许的数据。
- 样例必须由 `solution.py` 得出，不手算后未经验证直接写入。
- 支持 Markdown、原始 HTML、代码高亮和 LaTeX；不要依赖未验证的扩展语法。

## 隐藏出题者内容

需要保留在 Markdown 源文件、但不展示给选手的内容可写为：

```markdown
:::oj-remove
这里可以放出题思路、参考答案说明或内部备注。
:::
```

默认配置会从渲染题面和嵌入源码中删除整个区域。不要在其中放运行所必需的信息。
